# FA Ascend950 v3 FD combine：提前提交 LSE 写回（2026-10-13）

开启 LSE 时，24 组输入中 **23 组均值变快，20 组三轮均变快**。H64 的 combine 增量估算 **3.626 → 2.732 µs（下降 24.65%）**，完整 kernel 提升 **7.47%**；Q14 对应 **4.449 → 4.027 µs（下降 9.49%）**，完整 kernel 提升 **2.56%**。精度正常，116 项回归通过。

最终保留 combine 内的 LSE 写回重叠：提前提交搬运，延后完成等待。不修改主 attention 的切分、combine 分核、partial 格式或 FP32 数学计算。三轮拆分实验没有支持继续保留连续行搬运分支，因此该分支只保存在隔离实验副本中。

## 实现

- 原路径在 O 规约、Cast、O 写回及其完成等待之后，再计算写回地址并搬运最终 LSE。
- 候选在 `PrepareWeights()` 之后提交 LSE 写回，使其可与后续 partial O 搬运和规约重叠；在本行块 O 写回之后等待 LSE 完成，再进入下一行块。均衡分配与原分配两条路径均使用这一顺序。
- 单 token 连续 head 搬运、跨 head/多 batch 的散写，以及 Brcb 均保持原实现；只调整提交与完成等待的位置。
- LSE 与 O 的 UB 区域独立；没有增加 UB。`V_MTE3` 发布向量结果，`MTE3_V EVENT_ID1` 的等待在下一次复用 LSE 缓冲前完成。没有删除主 kernel 的 `SyncAll`。
- partial O、partial LSE、权重和累加仍为 FP32；累加顺序及分开的 Mul/Add 不变，仅最终 O 转换为公开输出类型。

实现见 [fd_combine.hpp](../csrc/ascend950/flash_attn_npu_3/fd_combine.hpp)。

## 性能方法

使用 [采集脚本](collect_fd_combine_ab.py)、[运行脚本](profile_fd_combine_sweep.py) 与 [汇总脚本](summarize_fd_combine_ab.py)，普通 `msprof --ai-core=off --task-time=on --ascendcl=off`。每组预热 50 次、测量 100 次。最终矩阵为物理 NPU 2 的基线、共享屏蔽参考、overlap 三版，三轮顺序为 baseline/off/overlap、overlap/off/baseline、baseline/off/overlap，保存在 `selected-ab-npu2/`。

完整 kernel 的净收益直接比较两版 full。主 FD 阶段保持不变，两版共用只屏蔽 combine 调用的 baseline-no-combine，分别计算 `full − 共享参考` 作为增量估算。这包含尾部及代码生成差异，不是独立 combine kernel 时间，也不能把完整净收益全部标成 MTE3 重叠时间。重复相同输入属于 warm-cache 测量。

共享机器上，输入准备前、实际调用前后和采集过程中检查进程；观察到测量期间并发则排除整次采集。实际调用前允许等待其他任务结束。仅在导出阶段出现的其他进程不改变已经完成的测量。任意组最大 Task Duration 超过其中位数三倍，也整次排除重采；不挑选单个样本。失败、被中断和排除的尝试保留。

## 连续搬运分支的取舍

NPU 2 上独立比较 baseline、仅 overlap、overlap 加连续搬运三版，4 个输入 × LSE 开关，每版三轮各 100 个测量样本。初始一轮后因增量收益不确定扩展为三轮，原始一轮保留在 quick-npu2，补测与统一记录在 ablation-npu2，没有跨卡混合。

LSE 开启时，连续搬运版相对仅 overlap 的完整 kernel 耗时变化如下，正数代表变慢：

| case | 三轮变化 µs | 平均变化 µs |
|---|---|---:|
| H32 | +0.057 / +0.064 / +0.017 | +0.046 |
| H64 | +0.228 / +0.207 / +0.091 | +0.176 |
| Q14 | +0.255 / -0.259 / -0.445 | -0.150 |
| D256 | +0.421 / -0.199 / -0.347 | -0.042 |

Q14/D256 的增量收益不稳定，H64 三轮都回退；最终保留更简单的仅 overlap 实现。H32/H64 不进入新增连续 token 分支，因此这些变化不能直接归为该分支 DMA 成本；代码生成、布局和测量状态也可能参与。没有硬件指标证明具体原因。

初期 NPU 1 上组合候选的不完整 24 组矩阵，以及 NPU 1/2/3 上受占用影响或未完成的尝试，不并入最终 `selected-ab-npu2` 的均值。当前报告只主张最终版本正式三轮数据支持的收益。
