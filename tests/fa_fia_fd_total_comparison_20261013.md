# 当前 FA / FIA：FD 泛化输入的完整 kernel 总耗时（2026-10-13）

## 结论

基于 FA 提交 `ef624b5`，构造 **42 组不同输入**；39 组实际进入 FA FD，完成 FA `num_splits=0`、FA `num_splits=16`、内置 FIA 三版的同卡三轮采集，分别测试 LSE on/off。39 组中 **31 组 FIA 也进入 FD**，另外 8 组 FIA 走非 FD，分表报告。剩余 3 组未进入 FA FD，不纳入性能矩阵。

**31 组两边均 FD 的输入，主 kernel 的整体水平已接近，但不同 shape 差异明显。开启 LSE 后，FA 额外的初始化 kernel 成为完整调用总耗时中的一项明确开销。**

| 口径：仅统计两边均 FD 的 31 组 | FA/FIA 耗时比的几何均值 | FA 更快的输入数 |
|---|---:|---:|
| LSE on，FA auto，仅主 kernel | 0.991，FA 约快 0.9% | 18 / 31 |
| LSE on，FA auto，所有计算 kernel 之和 | 1.093，FA 约慢 9.3% | 6 / 31 |
| LSE on，FA16，所有计算 kernel 之和 | 1.067，FA 约慢 6.7% | 10 / 31 |
| LSE off，FA auto，所有计算 kernel 之和 | 1.006，FA 约慢 0.6% | 15 / 31 |
| LSE off，FA16，所有计算 kernel 之和 | 0.964，FA 约快 3.6% | 19 / 31 |

几何均值对每个构造输入等权，不代表实际模型请求分布；“更快”按三轮均值计数，未对很小的差异作统计显著性判断。FA16 是补充对照，并非固定使用 16 splits 总会更快。

## 计时边界：主 kernel 与总耗时

普通 `msprof --ai-core=off --task-time=on --ascendcl=off` 的 `Task Duration(us)` 直接计时，**没有使用屏蔽 combine 版本，也没有用 full−no-combine 差分**。

- FA 的 `FAInfer` 已包含主 attention 计算、partial 写回、同步和 combine；本轮未启动独立 `FAFlashDecodeCombine`。
- LSE on 时，FA 的每次调用实际启动 **`aclnnInplaceFillScalar_FillAiCore_Fill` + `FAInfer`**。初始化来自 [mha_fwd.cpp](../csrc/ascend950/flash_attn_npu_3/mha_fwd.cpp) 中 `softmaxlse.fill_(infinity)`。当前 `FA auto` 各输入的初始化三轮均值为 **1.397–1.645 µs**。总耗时逐次按这两个 kernel 的 Task Duration 相加后统计。
- LSE off 时，FA 只启动一个 `FAInfer`；本轮 FIA 两种 LSE 模式都只启动一个 `FusedInferAttentionScore`，因此它们的总耗时等于主 kernel 耗时。
- 汇总程序按时间顺序验证每次调用的完整 kernel 序列：FA LSE-on 必须为同 stream 的 Fill→FAInfer，其余必须为一个 attention kernel。**从第一条调用开始，不允许有未计入的其他计算 kernel**。
- Q/K/V 生成、page table 的 Arange、FIA KV 布局预转换均在测量调用之前完成；这些准备 kernel 单独识别并排除。总耗时是调用内计算 kernel 的耗时之和，**不包含 CPU 调用、host tiling、内存分配、H2D/D2H 拷贝、kernel 间空隙或 synchronize 等待**，不是端到端接口延迟。

## 从总耗时看到的差异

1. **LSE 初始化值得单独优化。** 它是本次 profiler 直接观测到的额外 kernel，不是由差分推断出来的。后续可以检查 FD 路径是否完整写回所有有效 LSE，再考虑跳过初始化；空序列、无有效行、mask 等边界语义需要先验证。本轮只测量，没有修改实现。
2. **自动 split 策略仍值得调整，不能统一固定成 16。** H64/KV8192，FA auto 实际 28 splits，FIA 16；FA 总耗时 13.879 µs，改为 FA16 后 12.788 µs。KV32768 时，FA auto 28 splits 的 17.230 µs 则优于 FA16 的 18.797 µs。batch、KV heads 增多时也会重新分配 splits，见下表实际值。
3. **较大 Q 和变长输入的差距不仅是 LSE 初始化。** Q14 的 FA 主 kernel 15.912 µs、FIA 15.060 µs；变长 Q 的 `varq_ascending` 为 18.829 vs 14.239 µs，GQA `kvheads_8` 为 22.674 vs 18.492 µs。FA/FIA 实际 split 和分块不同，本次完整计时不能把这些差距全部归给 combine，需要进一步看主计算调度、分核与访存。
4. **D256 等大幅优势属于不同算法路径的对比。** 本轮 `d_256`、`fp16_d256`、`fp16_tail` 的 FIA `isFd=0`；FA 仍为 FD。两边输入逻辑相同、精度均正常，但不能用这些结果声称 FA 的 combine 比 FIA 快数倍。

## 输入一致性、版本与验证

- FA 和 FIA 使用同一确定性生成器，seed=1，Q/K/V 为 [-5,5) 均匀随机数后转 BF16/FP16。逐 case 验证 Q/K/V 原始字节 SHA256 相同；Q/KV 实际长度、head 分组、D、softmax scale、page table/page size 与非 causal 语义相同。
- Query 均为 TND。FA paged KV 为 `[page,128,KVH,D]`，FIA 为 `[page,KVH,128,D]`；FIA 的 permute/contiguous 提前完成。物理布局按各接口要求不同，逻辑值一致。两边没有强行使用相同 splits，表中给出实际配置。
- 当前 FA 的已编译隔离完整产物与提交后的 **43 个相关 C++/头文件/Python 文件**逐字节一致，原生 `.so` SHA256 为 `77923fa74ea333560e10e8b08b18a26bbe973818d596cfd53556b3d4857608e8`，显式加载该产物；本轮未重新构建或安装。FIA 使用 CANN 9.2.0 beta.2 的内置完整算子，清空 `ASCEND_CUSTOM_OPP_PATH`，每种实际路由的二进制路径/hash 均有记录。
- FA 的 39 组 × LSE 开关 × 两种 num_splits，共 **156 个实际下发 tiling 记录**与当前源码 host probe 逐项匹配，`flashDecodeFlag=1`。FIA 的 42 个候选 × LSE 开关，用 INFO plog 核验 `isFd`、tilingKey、split、分核和二进制；正式性能阶段关闭日志与 tiling hook。
- 全部正式性能使用物理 **NPU 5，Ascend950PR，28 AIC / 56 AIV**。每组预热 50 次，测量 100 次；三轮顺序为 `FA0→FA16→FIA`、`FA16→FIA→FA0`、`FIA→FA0→FA16`。共 9 次有效采集，**70,200 次测量调用 / 93,600 个测量计算 kernel**；预热不计入这些数字。
- 测量前后及期间监测设备进程，无外部进程进入测量窗口。本轮没有丢弃或裁剪任何性能样本；预设整次采集拒绝条件为外部进程争用或主 kernel 最大耗时 > 中位数 3 倍。本轮最大比值 1.207；加入初始化后的逐调用总耗时也通过 3 倍中位数检查。三轮均值范围完整保留，不是置信区间。
- 三版每种输入和 LSE 开关均通过独立 CPU FP32 attention 参考。BF16 O 容差为 `atol=0.03, rtol=0.02`，FP16 为 `0.005, 0.005`；LSE 为 `2e-4, 2e-5`。FA 最大 O 绝对误差 0.018642，FIA 为 0.018799；最大 LSE 绝对误差均不超过 2.0981e-5。**性能运行的 1,053 个输出张量与各自精度验证结果逐位一致**，LSE 开关得到的 O 也逐位一致。FA 与 FIA 不要求跨实现逐位相同。
- `batch_12` 在 FA 不走 FD、FIA 走 FD；`batch_16` 与 `kvheads_16` 两边均不走 FD，三者未纳入正式性能统计。短 KV 和其他 D 中 FA FD/FIA 非 FD 的 8 组保留在附表中。
